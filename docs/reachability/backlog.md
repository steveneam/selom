# Reachability backlog — what we built that nobody can reach

_Generated by the reachability ratchet on its first run, 2026-07-25. Enforced by
`app/backend/tests/test_reachability_guard.py`; the waiver table there is the machine-readable twin of
this document._

## Why this exists

"Shipped ≠ reachable" kept recurring and kept being re-discovered by expensive milestone reviews.
[[selom-shipped-not-reachable]] already prescribed the remedy — *"add a reachability guard test"* — and
that guard was never built, so the lesson survived only in memory, the weakest rung of the ratchet
ladder. It is built now.

**What it asserts:** every user-facing backend route is either reached by an FE call site or waived
with a reason and a tracking ID. A new endpoint with neither fails the build in the author's own run.
**Stale waivers fail too**, so the list can only shrink — a lane cannot bank its waiver after wiring
the surface up.

## What the first run found

**17 of 61 user-facing paths (28%) had no frontend call site.** The milestone review — a token-heavy
gauntlet + fe-review pass — had surfaced **2** of them. That gap is the argument for the guard: a
mechanical sweep found 8× more of this specific defect class than a careful human-style review, in
under a second, and it will keep finding it for free.

It also caught **three waivers I had guessed wrong** on the first run: I assumed `/export/cloud`,
`/import/local-state` and `/uploads/local/{key:path}` were unreachable; the scan proved they are
reached. The stale-waiver half worked before the ink was dry.

### The scan's limits, stated honestly

- **Granularity is the path, not the HTTP method.** `GET /datasets` and `POST /datasets` are one row.
  Inferring the verb at every call site — including raw `fetch` calls that pass `method` in an options
  object — would add false positives for little gain. A referenced path means the feature area is
  wired; per-verb coverage belongs to feature tests.
- **A referenced path is not a *working* surface.** The guard proves a call site exists, not that a
  user can find it or that it succeeds. It is a floor, not a ceiling — `fe-review`'s user-task
  walkthrough still does the affordance work.
- **Mocks and tests are excluded on purpose.** `mocks/handlers.ts` names nearly every path; counting it
  would let the MSW mock satisfy the guard for a route no product code calls — the "mock proves the
  wire, not the product" trap ([[selom-mock-is-wire-only-verify-real]]).

## How this backlog gets worked

Not as a batch. **Each waiver is removed by the change that wires its surface up** — and the guard
enforces that, because a stale waiver fails. So the list shrinks as real work lands, and its length is
an honest running measure of how much we have built that nobody can use.

**Sequencing view:** `R-02` is the highest-leverage row, because it is a *precondition* for the
unparked `OH-01` rather than a consequence of it. `R-01` + `R-03` are the largest user-visible loss and
overlap heavily. `R-04` gates the proposal's `F1`. `R-07` is a five-minute decision that should not sit
on a list.
