# ERG session findings — 2026-06-23 (T6)

Errors hit and lessons learned while shipping ERG Phase 2 (b-wave bar, Naka-Rushton
intensity-response, ISCEV methods), the publication export, and the figure-editor
cosmetics/Figure-data separation. Captured per the Ratchet (every lesson → a durable
artifact). **Fixed** items landed in code this session; **Open** items are real gaps to
fix later (mostly the shared engine — Codex lane).

## Fixed this session

1. **Naka-Rushton gate hid the headline signal.** The first honesty gate rejected the
   3'UTR rescue's fit (its noisy per-intensity curve wanted an artifact-steep slope that
   pinned at the bound) while keeping the weaker PDE6B — so the *best* responder looked
   unfit. **Fix:** auto-fit each condition's slope, fall back to a fixed physiological
   slope (n=1) where under-constrained, and expose `nr_slope` + `min_r2` in Figure data.
   **Lesson:** an honesty gate that drops the very signal the figure exists to show is
   worse than no gate — give it a fallback + user control, don't just hide.

2. **`load_skill` read `skill.json` with the platform encoding (cp1252), not UTF-8.**
   Crashed on `ⁿ` (U+207F) in a new skill.json and silently mangled `µ`/`·`/em-dashes in
   catalog text for the existing skills (it only "worked" because those bytes happened to
   be cp1252-decodable). **Fix:** `p.read_text(encoding="utf-8")`. **Lesson:** always read
   JSON/text with an explicit `encoding="utf-8"` on Windows — the default is locale-dependent.

3. **`theme._style_axis` stripped intentional axis specs.** Rebuilding an axis dropped
   `tickangle`/`rangemode`/`tickvals`/`ticktext`/`tickmode` — which had been silently
   flattening the angled gene labels in `markers`/`cepo` and un-pinning `pvca`'s zero axis,
   and would have erased the new b-wave bar's category labels. **Fix:** preserve those keys
   in the keep-list. **Lesson:** a restyle that *rebuilds* a sub-object must carry over the
   author's explicit structural specs, not just colours/fonts.

4. **The b-wave bar silently included a QC-failed eye.** `erg_metrics_long.csv` had no QC
   column, so the cataract 3'UTR eye (251_RE) was averaged in (n=4 instead of 3). **Fix:**
   added a `qc_excluded` column to the data + the skills honour it. **Lesson:** a graph that
   excludes an eye from *selection* must exclude it from the *quantitative graph* too —
   carry QC flags in the canonical table, not just the selection report.

## Resolved (T7, 2026-06-23) — the layered-ingest fix

Items 5–8 below were captured as open at the end of T6. **All are now fixed (T7).** The
**real root cause was misdiagnosed in T6**: it was NOT `engine.ingest`. The engine already
classified the ERG metrics CSV correctly as `generic_table` with all columns intact, and the
real run path reads from the saved file (no column stripping). The bug lived entirely in the
**FE intake**: `lib/intake/mock.ts::detectModality(filename)` mapped *every* `.csv` →
`"bulk RNA-seq"`, and `mockQcReport("bulk RNA-seq")` returned a hardcoded `24 × 22,000` minus
"drop low-count genes (−3,898)" = **the bogus "24 × 18,102" + gene-subset cleaning** — never
derived from the real `/data/inspect`. (Lesson: when a finding says "the engine misclassifies",
verify against the engine directly before believing the FE's displayed verdict — the FE was a
mock.) The fix follows the owner's layered steer (commits `2e80ef2` + `15698aa`):

- **Engine (`engine/cleaning.py`):** `profile_data()` — layered, honest data-type label
  (L1 format `.iwxdata`=certainly ERG · L2 high-precision columns a-/b-wave+intensity=ERG ·
  L3 modality; never false-positives — an untypable table stays a neutral "Data table") +
  `plan_cleaning()` — a **dynamic** cleaning plan keyed off modality (count matrix → real
  steps; results/generic/ERG → honest EMPTY plan, no gene cleaning). `route_profile()` routes a
  recognized ERG table to the electrophysiology skills.
- **FE:** the intake now classifies the real payload via `/data/inspect` (fail-soft), the
  cleaning pane is dynamic (empty-state "used as-is" for non-matrix), the data-type label is
  shown with a confidence + reason + an override (the L3 user layer).
- **#6 (error surfacing):** the run endpoint now catches a runner `ValueError` → HTTP 400 with
  the real cause ("missing required columns […]"), distinct from a 5xx outage.
- **#7 (shape):** the shape now comes from the real engine (`210 × 11` for the metrics CSV,
  `63,000 × 8` for the waveforms) — the "24 × 18,102" was the hardcoded mock.
- **#8 (QC false-positive):** never reproduced on the real path — `_qc_frame` only blocks when
  there are zero numeric columns; the metrics table has many, so it's `unclassified` (info), not
  blocked. It was the same mock artifact.

Verified live end-to-end (real backend + real data, NOT dev:mock): drop `erg_metrics_long.csv`
→ "ERG / electrophysiology (likely)", no gene cleaning, run → the real Naka-Rushton figure.

## Workflow lessons (durable, cross-project)

9. **Verify skill-specific output on the REAL backend + REAL data — never `dev:mock`.**
   `dev:mock` returns a canned stub UMAP for *every* skill (`mocks/handlers.ts` →
   `stubUmapFigure()` ignores `:skillId`), which repeatedly showed a UMAP for ERG skills and
   caused real confusion. The mock proves the *wire/UI path*, not the figure *content*. For
   anything skill-specific (does the right figure render?), run `npm run dev` against a live
   `uvicorn` backend with the real data. (Owner steer 2026-06-23.)

10. **The dev `?demo=<id>` shortcut passes a *bare* skill id**, so catalog lookups by the
    namespaced id miss (the editor showed "erg_traces" instead of "Selom ERG Trace Grid")
    until a `selom.`-prefixed fallback was added. Minor, but lookups should accept both.

11. **In-memory upload bytes are lost on navigation/reload** — re-running a skill after
    navigating needs a re-upload (the dataset metadata persists; the `File` does not).

## IA decision recorded (figure editor)

- **Editor = cosmetics only** (colours/lines/labels/axes — JSON-Patch, instant). A slim
  skill-identity strip sits atop the inspector (which skill made the figure + a hand-off).
- **Figure data = every input that changes the data's shape/metric/output** (smoothing,
  scale, Naka-Rushton slope, R² gate) + the data-check/data-fit diagnostics — editing one
  re-runs into a new version. Inputs live in **one** place. (Owner principle 2026-06-23.)
